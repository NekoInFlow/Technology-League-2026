# Рекомендации по оформлению Инженерной книги

## Визуальная структура

### Чёткая навигация
- Используйте оглавление с номерами страниц
- Нумеруйте страницы — рекомендуется ставить номер команды вверху каждой страницы
- Разделяйте разделы заголовками

### Чертежи и диаграммы
- Используйте технические чертежи для ключевых узлов Робота
- Показывайте эволюцию дизайна — от черновых эскизов до финальной версии
- Используйте схемы САПР где это возможно
- Материалы в чертежах должны соответствовать текущей версии Робота

### Текст и изображения
- Размер шрифта не менее 10 пт
- Избегайте узких шрифтов, ухудшающих читаемость
- Подписывайте все рисунки, фото и схемы

## Структура по номинациям

Рекомендуется организовать книгу так, чтобы эксперты могли быстро найти информацию по каждой номинации:

| Раздел | Содержит |
|--------|----------|
| **Инженерное решение** | Архитектура системы управления, схемы контроллеров, питание, связь |
| **Продуманный подход** | История проектирования, варианты решений, расчёты, испытания |
| **Программная инженерия** | Описание алгоритмов, использование датчиков, тестирование ПО |
| **Инновационный подход** | Оригинальные решения, прототипирование, сравнение подходов |
| **Дизайн Робота** | Чертежи/САПР, компоновка, качество сборки |
| **Развитие сообщества** | Деятельность популяризации, наставничество, привлечение |
| **Взаимодействие** | Работа с наставниками, инженерами, вузами, компаниями |

## Общие рекомендации

- Инженерная книга должна быть профессионально оформлена — это отражение серьёзности подхода команды
- Не перегружайте страницу текстом — используйте таблицы и списки вместо длинных абзацев
- Все данные должны быть точными и проверенными
- Эксперты будут сравнивать Инженерную книгу с заявленными решениями на поле — соответствие должно быть полным
